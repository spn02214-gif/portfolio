Order Risk Decision Layer

ERP 주문 데이터를 위험 인지 및 대응 우선순위로 전환하는 운영 의사결정 MVP

ERP는 주문 이력을 보관하지만, 현장 담당자에게 “지금 무엇부터 처리해야 하는지”를 알려주지는 않습니다. 이 프로젝트는 211건의 비식별 ERP 주문 데이터를 기반으로 리스크 신호를 정의하고, 위험 주문을 우선순위화하는 규칙 기반 Decision Layer를 설계한 사례입니다.

01

Problem

Problem 01. Decision Delay

ERP는 정보를 보여주지만, 처리 순서는 따로 판단해야 했습니다.

ERP에는 주문, 납기, 출하 정보가 존재하지만 담당자는 지금 어떤 주문부터 확인해야 하는지 별도로 판단해야 했습니다.

Problem 02. Execution Gap

조회 이후의 대응 흐름이 개인 메모와 대화로 흩어졌습니다.

대응은 채팅, 이메일, 개인 메모로 분산되어 누락, 지연, 긴급 전환의 원인을 추적하기 어려웠습니다.

Problem 03. Risk Visibility

반복 리스크 신호가 대응 순서로 연결되지 않았습니다.

월말 실적 집중, 짧은 리드타임, 반복 긴급 전환 고객 같은 신호는 있었지만 사전 대응 순서로 묶는 구조가 없었습니다.

Insight

핵심 문제는 데이터 부족이 아니라, 기록 데이터를 실행 우선순위로 바꾸는 중간 의사결정 레이어의 부재였습니다.

02

Solution

Decision Layer는 ERP 데이터를 대체하지 않습니다. 기존 주문 기록 위에 리스크 신호를 해석하고, 담당자의 다음 행동과 대응 기록으로 이어지게 하는 경량 구조입니다.

Record
ERP 주문 데이터를 공통 주문 단위로 정리

주문번호, 납기, 출하 상태, 긴급 플래그 등 담당자가 판단에 쓰는 필드를 기준으로 데이터를 정리했습니다.

Detect
리스크 신호 정의

납기 초과, 임박 납기, 짧은 리드타임, 미출하 상태, 긴급 플래그를 위험 판단 신호로 정의했습니다.

Prioritize
복수 신호를 대응 우선순위로 변환

신호의 중요도에 따라 가중치를 부여하고 주문별 위험 단계를 Normal, Warning, Critical로 분류했습니다.

Act
담당자 확인과 인수인계 기록으로 연결

분석 결과가 화면에서 끝나지 않고 담당자 확인, 메모, 인수인계 기록으로 이어지는 실행 흐름을 설계했습니다.

04

Impact

아직 실사용자 검증 전 단계이므로, 결과를 “업무 방식이 이미 바뀌었다”가 아니라 “바꿀 수 있는 MVP 흐름을 설계했다”로 정리했습니다.

ERP 조회 중심 업무를 우선순위 판단 구조로 전환할 수 있는 MVP 흐름 설계
전체 주문을 훑는 방식에서 먼저 확인할 대상을 분리하는 방식으로 전환했습니다.
MVP Flow

반복적으로 긴급 전환이 발생하는 고객을 사전 대응 후보군으로 볼 수 있게 했습니다.

실제 운영 데이터 형태에 가까운 주문 라인에 리스크 기준을 적용해 분류 가능성을 확인했습니다.

05

Implementation

Lightweight Structure

ERP 교체 없이 기존 업무 흐름 위에 얹는 구조

새 시스템 도입보다 담당자가 이미 쓰는 주문 데이터와 대응 흐름을 보완하는 데 초점을 맞췄습니다.

Rule Before ML

211건 규모에서는 검증 가능한 규칙을 먼저 선택

211건 규모의 데이터에서는 ML 적용보다 검증 가능한 규칙을 먼저 정의하는 것이 적절하다고 판단했습니다.

PM Role

기능보다 실행 구조를 정의

PM의 역할을 화면 기능 나열이 아니라, 기록, 판단, 대응, 인수인계가 연결되는 운영 구조 설계로 두었습니다.

Extension Path

향후 AI 판단 레이어로 교체 가능한 구조

Phase 1은 Rule-based Decision Layer로 설계하고, 데이터가 누적되면 AI 판단 레이어로 확장할 수 있게 했습니다.
